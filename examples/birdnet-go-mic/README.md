# BirdNET Go microphone over a tailnet

This hero case adds ESP32 Tailnet to
[`bagdeabhishek/m5stack-atom-voices3r-birdnet-mic`](https://github.com/bagdeabhishek/m5stack-atom-voices3r-birdnet-mic).
The microphone still joins ordinary Wi-Fi for its uplink, but BirdNET Go can be
on a different physical network and connect to the mic's stable `100.x.y.z`
address.

The integration has been compiled and flashed on an M5Stack Atom VoiceS3R
against pioarduino `55.03.38`, ESP-IDF 5.5.4, and Arduino 3.3.8. The resulting
image uses approximately 1.49 MB flash and 59 KB static RAM before runtime
buffers. Browser authorization and identity persistence across an OTA reboot
were verified: the board reconnected with the same tailnet address and no new
login prompt. HTTP, 48 kHz I2S capture, and RTSP OPTIONS were verified over the
LAN. End-to-end service checks over the `100.x.y.z` address require an
authorized Tailscale peer; the isolated build environment used here had no
Tailscale interface or `100.x` route.

## Apply it

From a clean checkout of the BirdNET mic repository:

```sh
git apply /path/to/esp32-tailnet/examples/birdnet-go-mic/birdnet-tailnet.patch
git submodule add https://github.com/bagdeabhishek/esp32-tailnet.git external/esp32-tailnet
```

Build and flash:

```sh
pio run -e m5stack-atom-voices3r
```

Open the microphone's LAN Web UI, choose **Tailscale**, and click **Authorize
with Tailscale**. The page polls until the node receives its `100.x.y.z`
address. No auth key needs to be compiled into the image. Enrollment survives
reboots, OTA updates, and Wi-Fi changes. The same page provides a separately
confirmed **Clear Tailscale identity** action when re-enrollment is intentional;
it does not clear Wi-Fi or BirdNET settings.

For fleet or fully unattended provisioning, copy `TailnetSecrets.h.example` to
the ignored `TailnetSecrets.h` and supply a temporary auth key. Do not put auth
keys in `platformio.ini`, committed headers, build logs, or issue reports.

## What the patch does

- changes the firmware to the supported mixed `arduino, espidf` build;
- adds the ESP32 Tailnet component through an IDF path dependency;
- renames the sketch to C++ and supplies the few declarations previously
  generated by Arduino's `.ino` preprocessor;
- starts the tailnet after Wi-Fi provisioning succeeds;
- exposes a keyless browser authorization flow at `/tailscale` and status JSON
  at `/api/tailnet`;
- exposes explicit identity removal at `POST /api/tailnet/clear`, protected by
  the firmware's mutation-request header;
- calls `rebind()` when Wi-Fi reconnects;
- keeps every server bound normally, preserving LAN access;
- advertises the tailnet address in the Web UI, MQTT discovery, RTSP SDP,
  `Transport` source, `Content-Base`, and RTP info;
- retains `lan_ip` in status JSON for local diagnostics.
- selects the board's 8 MB dual-OTA partition table explicitly, avoiding the
  mixed-framework default 1 MB factory partition.

## Connect BirdNET Go

Wait for the serial log to print a line like:

```text
Tailnet ready: rtsp://100.80.12.34:8554/audio1
```

Use that URL as the RTSP source in BirdNET Go. The second stream remains
available at `/audio2`. The Web UI is reachable at
`http://100.80.12.34/` from an authorized tailnet node.

RTSP interleaved TCP is the simplest first validation. UDP RTP is also wired to
advertise and route through the overlay, but test it across the exact NAT and
firewall path you plan to deploy. The package may choose a DERP relay when a
direct path cannot be established.

After enrollment, disable node-key expiry for an unattended microphone. If you
used an auth key, revoke it when your policy allows. Rebuilding without a key is
supported because the node identity is stored in NVS.

## Updating the patch

The patch targets the repository state validated on 2026-10-11. If upstream
changes move the RTSP or Wi-Fi lifecycle code, apply it with `git apply --3way`
and preserve the same integration boundaries: start after an uplink exists,
rebind after an uplink change, and use `serviceIP()` only for addresses exposed
to clients.
